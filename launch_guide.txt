Launch Guide
------------
This project runs on ROS Noetic and uses a UR10 with an Intel RealSense L515 for ball detection, prediction, and interception. Below are the exact steps to bring everything up, plus the two interception criteria you can choose from.

1) Start the RealSense L515 (aligned, synchronized RGB-D)
---------------------------------------------------------
Install RealSense Camera ROS Wrapper (ROS1 legacy branch):
https://github.com/IntelRealSense/realsense-ros/tree/ros1-legacy

Launch camera with aligned depth and RGB, synchronized timestamps:
roslaunch realsense2_camera rs_camera.launch   enable_color:=true enable_depth:=true align_depth:=true   enable_sync:=true color_width:=1280 color_height:=720 color_fps:=30   depth_width:=1280 depth_height:=720 depth_fps:=30

2) Bring up the ICS UR10 visualization
--------------------------------------
This puts robot, camera, and ball trajectories in the same workspace so everything is visible in RViz.

roslaunch tum_ics_ur10_bringup bringUR10.launch

3) Launch the tracking node (ball detector & 3D center)
-------------------------------------------------------
This node detects the ball and publishes its 3D center in the camera frame (filtered).

rosrun l515_tools ball_tracker.py

Publishes (typical):
/ball/meas_point (geometry_msgs/PointStamped)
/ball/meas_pose (geometry_msgs/PoseStamped)
/ball/meas_path (nav_msgs/Path)

4) Choose interception criterion
--------------------------------
A) PLANE INTERCEPTION CRITERION
--------------------------------
1) Predictor (KF + plane intercept)
   Predicts ball motion with a Kalman Filter and computes the plane intercept point & time.
   rosrun l515_tools ball_predictor.py

2) Transformation & orientation publisher
   Converts interception point from camera frame to world frame and generates EE orientation from velocity.
   rosrun l515_tools interception_publisher.py

B) MINIMUM-DISTANCE CRITERION
------------------------------
1) Predictor (KF only)
   Produces filtered position and velocity; no plane logic here.
   rosrun l515_tools ball_predictor_min_dist.py

2) Bridge/optimizer node
   Optimizes for the time/point of minimum distance between the EE and the predicted ball trajectory,
   transforms to world frame, and generates target pose (position + orientation from velocity).
   rosrun l515_tools bridge_min_distance.py


5) Launch the controller (move UR10 to target)
----------------------------------------------
This controller consumes the published target pose and commands the robot.

roslaunch tum_ics_ur10_controller_tutorial testBallCatcherController.launch

6) Notes & tips
---------------
- Time sync: enable_sync:=true is important so RGB and depth timestamps match for stable 3D centers.
- Aligned depth: align_depth:=true ensures depth is in the color frame, simplifying projection.
- Switching criteria: stop the predictor/bridge nodes for one method before launching the other to avoid topic conflicts.

8) Typical run order (example)
------------------------------
Plane criterion:
1. RealSense (Step 1)
2. UR10 bringup (Step 2)
3. ball_tracker.py
4. ball_predictor.py
5. interception_publisher.py
6. Controller launch

Minimum-distance criterion:
1. RealSense (Step 1)
2. UR10 bringup (Step 2)
3. ball_tracker.py
4. ball_predictor_min_dist.py
5. bridge_min_distance.py
6. Controller launch



To run on real robot:
set static IP to 192.168.1.3.
Modify .bashrc

rosmaster_ur10()
{
export ROS_MASTER_URI=http://192.168.1.3:11311
export ROS_IP=192.168.1.3
}
rosmaster_local()
{
export ROS_MASTER_URI=http://localhost:11311
export ROS_IP=127.0.0.1
}
